# outputguard-js 2.0 Plan

## Goal

Make outputguard-js feel like a production structured-output toolkit rather than a JSON repair utility. Version 2.0 keeps JSON as the default, adds format-aware workflows, and gives application code first-class retry and batch primitives.

## Implemented Scope

### 1. Format-Aware Core

JSON remains the default. Public validation, repair, parse, retry-prompt, `OutputGuard`, reports, exceptions, and CLI commands accept `format` / `--input-format` for:

- `json`
- `yaml` / `yml`
- `toml`
- `python` / `python-literal` / `literal`
- `auto`
- `forced-json-off`

Generic repairs such as fence stripping preserve non-JSON syntax where possible.

### 2. Guarded Generation

`guardedGenerate()` wraps any provider function:

- Calls `generate(prompt, context)` with attempt metadata.
- Validates and optionally repairs each response.
- Builds targeted retry prompts from schema errors.
- Returns every attempt for observability.
- Supports strict `repair: false` mode.
- Supports `throwOnFailure` via `GuardedGenerationError`.

This replaces the manual retry-loop pattern in application code without depending on OpenAI, Anthropic, Vercel AI SDK, or any other provider SDK.

### 3. Batch Processing

`validateBatch()` and `repairBatch()` support corpus checks, eval fixtures, and production log audits:

- Preserve per-item index and input.
- Return full per-item results.
- Summarize total, valid, invalid, repaired, parse failures, schema failures, success rate, formats, and strategy counts.
- CLI `outputguard batch` validates a JSON array of output strings and returns JSON or text summaries.

### 4. Documentation And Metadata

The README now documents the 2.0 APIs, supported formats, batch CLI, strategy count, dependency set, and current test count. Package metadata is bumped to `2.0.0` and includes keywords for guardrails and batch processing.

## Non-Goals

- No provider SDK dependencies.
- No schema generation from TypeScript types.
- No release automation changes.
- No real-model API sweep inside the JS package. The new batch API is the foundation for that work without requiring credentials in the test suite.

## Verification Contract

2.0 is considered complete when:

- Focused red/green tests cover guarded generation and batch helpers.
- Full test suite passes.
- TypeScript typecheck passes.
- Build passes.
- Lint passes.
- `git diff --check` passes.
- README and package metadata describe the implemented APIs accurately.
